# AimDial

在瓦罗兰特游戏靶场实测，用中等难度 30 个机器人的击杀数量比较灵敏度。
网页负责给出测试档位和记录成绩，鼠标输入、视角和射击均由游戏处理。

## 本地运行

```bash
npm install
npm run dev
npm test
npm run build
```

Node >= 18。

## 使用流程

先在首页选一种模式：

| 模式 | 适用的人 | 需要填 | 轮次 |
|---|---|---|---|
| **微调现有灵敏度** | 已经有个大致顺手的数值，只想把它调准 | DPI + 当前灵敏度 | 约 12–15 轮 |
| **第一次找灵敏度** | 还没有确定的数值，愿意从头试出来 | 只要 DPI | 约 19 轮 |

共同的部分：

1. 填写鼠标 DPI（微调模式还要填游戏内灵敏度）。
2. 网页给出每个档位，按游戏输入精度保留三位小数；重复档位合并，取整为零的档位不参与。
   步宽不是固定的百分比，而是固定的**手部移动量**：以 250 eDPI 为基准，每一步对应约 3.9 cm 的
   360° 转身距离，再逐级收到 2.0 / 1.0 / 0.5 cm；换到具体玩家身上，中位约 4.4 cm，p10–p90 落在
   3.0–6.5 cm。所以灵敏度越高，一步的百分比就越小（0.150 时约 ±20%，0.400 时约 ±3.2%）。
3. 将游戏内灵敏度改为本轮显示的数值，保持 DPI 不变。
4. 在靶场选择中等难度，完成 30 个机器人测试。整个过程中保持相同武器、站位、护甲及射击方式。
5. 回网页输入击杀数量（0–30 的整数），提交后继续下一轮。填错可撤销上一轮。
6. 如果外侧档初测领先，网页会交错复测 6 轮（3 对，每一对里新旧各一轮，且每对交换先后顺序）。
   只有挑战档**每一对**都领先、平均至少多击杀 1 个，才会升级为新基准。
7. 没有明确提升，就把步宽收窄一半继续找；最小一档仍无提升时结束。

**两种模式的区别在搜索范围，不在措辞：**

- 微调模式**只围绕你给的值**工作（例如 0.320 → 首轮测 0.295 / 0.320 / 0.347）。如果外侧档在完整复查里赢了，
  说明你给的值偏差太大，程序会立刻停下并建议改用「第一次找灵敏度」，而不是用三十轮一格一格爬过去。
- 新玩家模式**不需要你给灵敏度**，从职业分布中心 250 eDPI 开始对称粗扫 7 个点
  （94 → 662 eDPI，顺序为 中心→高→低→更高→更低），成绩最好的那档成为起点，再围绕它细调。

同分或分差不足 1 杀时保留最近确认的基准灵敏度。测试报告说明实际测过的设置及比较结果，不声称找到唯一数学最优值。

### 结果页的职业选手参考

结果页会把你的 eDPI 放进 540 位公开设置的职业选手中：给出一条分布条（职业选手的 p10–p90，
你的位置标红），以及数值最接近的几位选手及其 DPI × 灵敏度。

数据来自 [ValorantHub](https://valoranthub.com/proplayers)（2026-11-07 抓取），打包在
`src/lib/prosData.js`。这是**参考，不是目标**——职业选手的数字属于不同的手、鼠标垫和位置，
页面文案里也写明了这一点，以你自己测出来的结果为准。

匹配按**对数距离**排序：灵敏度是乘性的，240 与 250 的差距和 480 与 500 相同，
按绝对 eDPI 排序会让高灵敏度选区挤满列表。12% 以内没有选手时，页面会直说没有可对照的人，
而不是硬凑几个差很远的。

### 步宽为什么这样定
旧版是固定比例 ×1.25 / ×1.12 / ×1.06。同一个比例对不同灵敏度的玩家是**完全不同的手部动作**：
在 540 位公开设置的职业选手分布上（[ValorantHub](https://valoranthub.com/proplayers)，核对于 2026-10-27，
中位 eDPI 240、平均 252、p25 192、p75 280），旧的 ×1.25 一步等于中位选手 **10.9 cm** 的 360° 转身距离，
p90 更是 16.3 cm——远超「一个台阶」的手感。改用固定物理距离后，94% 的职业选手落在 2–8 cm 的首档内，
旧方案只有 12%。新玩家模式的粗扫区间同样取自这份分布（p10–p90 为 160–344，粗扫覆盖 94–662 以留余量）。


## 数据与限制

- 每次录入、撤销及修改待提交的击杀数都会实时写入当前浏览器；重新打开页面可点击“继续测试”，恢复当前档位、比较阶段及未提交输入。
- 进度存储在当前浏览器的 localStorage，手机与电脑之间不会自动同步。保存失败会明确显示错误。
- 完成后的推荐值、各档平均成绩、成对提升和逐轮成绩保存为报告；点击首页历史记录可查看详情。历史与草稿清理通过同一次写入完成，重复打开报告不会创建重复记录。
- 旧版网页测试历史保留并标为“旧版”，与靶场成绩区分。
- 不自动修改游戏设置或读取游戏成绩；均由玩家手动操作。
- 练习、疲劳和随机发挥会影响成绩；交错顺序与三对成对比较只能减少部分影响。基准设置的成对成绩下降至少 3 杀时会提示状态波动。
- 全部候选均达到 29–30 杀或均只有 0–1 杀时，中等难度的区分能力不足，报告会提醒玩家检查难度或测试条件。
- 页面不展示 cm/360°、eDPI 等换算值：它们对大多数玩家没有参考意义。换算函数仍保留在 `lib/sens.js`，只供内部与测试使用。

## 部署到 Vercel

这是一个纯静态的 Vite 单页应用，无需服务端、无需环境变量。

### 方式一：Git 仓库导入（推荐）

1. 把项目推到 GitHub / GitLab。
2. 在 Vercel 打开 **Add New → Project**，导入该仓库。
3. 框架预设选 **Vite**（`vercel.json` 已写明 `buildCommand` / `outputDirectory`，通常无需改动）。
4. **Deploy**。之后每次 push 到默认分支都会自动重新部署。

### 方式二：Vercel CLI

```bash
npm i -g vercel
vercel          # 首次会引导你关联项目，生成 preview 部署
vercel --prod   # 发布到生产域名
```

`vercel.json` 已包含 SPA 回退规则（所有路径重写到 `/index.html`），所以直接访问子路径或刷新不会 404。构建产物路径固定为 `dist/`，与 `npm run build` 一致。

## 当前流程

- `SetupScreen.jsx`：DPI 与当前灵敏度输入，常用档位可一键点选。
- `CalibrationScreen.jsx`：每轮设置说明、击杀数录入与撤销。
- `rangeCalibration.js`：按手部移动量标定的步长阶梯、交错成对确认、输入校验与不可变计划。
- `storage.js`：实时草稿保存、确定性计划恢复及历史报告。
- `useCalibration.js`：会话与 React 的桥接。
- `ResultScreen.jsx`：推荐档位、平均击杀和逐轮成绩。

旧网页射击场模块已从主流程断开，不再用于本版评分。
