# AimDial

在瓦罗兰特游戏靶场实测，用中等难度 30 个机器人的击杀数量比较灵敏度。
网页负责给出测试档位和记录成绩，鼠标输入、视角和射击均由游戏处理。

## 本地运行

```bash
npm install
npm run dev
npm test
npm run build
```

Node >= 18。

## 使用流程

先在首页选一种模式：

| 模式 | 适用的人 | 需要填 | 轮次 |
|---|---|---|---|
| **微调现有灵敏度** | 已经有个大致顺手的数值，只想把它调准 | DPI + 当前灵敏度 | 约 5–15 轮 |
| **第一次找灵敏度** | 还没有确定的数值，愿意从头试出来 | 只要 DPI | 约 10–20 轮 |

共同的部分：

1. 填写鼠标 DPI（微调模式还要填游戏内灵敏度）。
2. 网页给出**这一轮**要测的灵敏度，按游戏输入精度保留三位小数。每次给的数值都不一样，都是根据你前面
   打出来的成绩挑的。
3. 将游戏内灵敏度改为本轮显示的数值，保持 DPI 不变。
4. 在靶场选择中等难度，完成 30 个机器人测试。整个过程中保持相同武器、站位、护甲及射击方式。
5. 回网页输入击杀数量（0–30 的整数），提交后继续下一轮。填错可撤销上一轮。

**大致过程：**

先从你现在的数值出发，上下各试几个，看看两边手感差多少。之后每测一轮都会重新比较一遍，
挑下一个最值得试的数值。当最好的那个明显比其它都好时结束；如果几个数值表现几乎一样，
会直接告诉你挑顺手的即可，不会硬选一个。

两种模式只在起点上不同：微调模式从你给的数值开始，新玩家模式从职业选手最常见的数值开始。

### 为什么要重复测几轮

同一个数值，两次打出来的成绩本来就会有起伏，差一两杀完全可能只是手感问题。所以好成绩会回头
再确认，测的轮数多了结论才可靠；几个数值始终咬得很近时，测试会坦白说明分不出高下，而不是靠
一次发挥就下结论。

### 结果页的职业选手参考

结果页会把你的 eDPI 放进 540 位公开设置的职业选手中：给出一条分布条（职业选手的 p10–p90，
你的位置标红），以及数值最接近的几位选手及其 DPI × 灵敏度。

数据来自 [ValorantHub](https://valoranthub.com/proplayers)（2026-11-07 抓取），打包在
`src/lib/prosData.js`。这是**参考，不是目标**——职业选手的数字属于不同的手、鼠标垫和位置，
页面文案里也写明了这一点，以你自己测出来的结果为准。

匹配按**对数距离**排序：灵敏度是乘性的，240 与 250 的差距和 480 与 500 相同，
按绝对 eDPI 排序会让高灵敏度选区挤满列表。12% 以内没有选手时，页面会直说没有可对照的人，
而不是硬凑几个差很远的。

## 数据与限制

- 每次录入、撤销及修改待提交的击杀数都会实时写入当前浏览器；重新打开页面可点击“继续测试”，恢复已测轮次并接着算出下一轮该测什么。
- 进度存储在当前浏览器的 localStorage，手机与电脑之间不会自动同步。保存失败会明确显示错误。
- 完成后的推荐值、各档平均成绩和逐轮成绩保存为报告；点击首页历史记录可查看详情。历史与草稿清理通过同一次写入完成，重复打开报告不会创建重复记录。
- 此前保存的历史记录会标注版本，与新的成绩区分开。旧版本的未完成进度无法沿用，会提示重新开始。
- 不自动修改游戏设置或读取游戏成绩；均由玩家手动操作。
- 练习、疲劳和随机发挥会影响成绩。多测几轮能抵消一部分起伏，但连续多轮成绩明显下滑时仍建议休息后再测。
- 全部候选均达到 28 杀以上或均只有 0–1 杀时，中等难度的区分能力不足，报告会提醒玩家检查难度或测试条件。
- 页面不展示 cm/360°、eDPI 等换算值：它们对大多数玩家没有参考意义。换算函数仍保留在 `lib/sens.js`，只供内部与测试使用。

## 部署到 Vercel

这是一个纯静态的 Vite 单页应用，无需服务端、无需环境变量、无需数据库。
所有数据都存在访问者自己的浏览器 localStorage 里，所以每个人打开同一个部署链接，
看到的是各自独立的记录。

### 方式一：一键部署（推荐）

点击下面的按钮：

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2FHenMie%2FAimDial)

1. 在 Vercel 登录（可用 GitHub 账号）。
2. 仓库名保持默认或改成自己喜欢的名字，点击 **Create**。
3. 等构建完成，拿到 `<项目名>.vercel.app` 域名即可使用。

Vercel 会新建一份 fork 到你的账号下，之后你在自己那份仓库里的改动会继续自动部署；
想跟进上游更新，从 `HenMie/AimDial` 同步即可。

### 方式二：导入现有仓库

1. 把项目推到 GitHub / GitLab。
2. 在 Vercel 打开 **Add New → Project**，导入该仓库。
3. 框架预设会被 `vercel.json` 设为 **Vite**，构建命令、输出目录、SPA 回退都已写好，直接 **Deploy**。
4. 之后每次 push 到 `main` 都会自动重新部署。

### 方式三：Vercel CLI

```bash
npm i -g vercel
vercel          # 首次会引导你关联项目，生成 preview 部署
vercel --prod   # 发布到生产域名
```

### 配置说明

`vercel.json` 里固定了以下几项，因此从网页导入或从 CLI 部署的结果一致：

| 字段 | 值 | 作用 |
|---|---|---|
| `framework` | `vite` | 用 Vite 预设，不依赖手选框架 |
| `installCommand` | `npm ci` | 按 `package-lock.json` 精确安装依赖 |
| `buildCommand` | `npm run build` | 与本地构建完全一致 |
| `outputDirectory` | `dist` | 静态产物目录 |
| `trailingSlash` | `false` | 固定不带尾斜杠，避免同名路由重复 |
| `rewrites` | `/(.*)` → `/index.html` | SPA 回退：直接访问子路径或刷新不会 404 |

`vite.config.js` 里的 `base: '/'` 保证产物使用以 `/` 开头的绝对资源路径，正好对应 Vercel 从根路径托管的静态文件；那里配置的 `server.host` 只作用于本地开发服务器，不影响线上。

**不需要 Node 版本配置**：`package.json` 的 `engines.node` 只写了 `>=18`，Vercel 会使用默认的 Node 22，满足要求。

## 当前流程

- `SetupScreen.jsx`：DPI 与当前灵敏度输入，常用档位可一键点选。
- `CalibrationScreen.jsx`：每轮设置说明、击杀数录入与撤销。
- `rangeCalibration.js`：整套搜索。`points()` 汇总每档的全部轮次并给出标准误，`fitCurve()` 用全部历史
  拟合响应曲线，`proposeNext()` 选下一轮，`derive()` 若停止条件成立则收尾。状态是 `setup + runs` 的
  纯函数，撤销与草稿恢复都靠重放，没有第二条代码路径。
- `storage.js`：实时草稿保存、确定性计划恢复及历史报告。
- `useCalibration.js`：会话与 React 的桥接。
- `ResultScreen.jsx`：推荐档位、平均击杀和逐轮成绩。

旧网页射击场模块已从主流程断开，不再用于本版评分。
